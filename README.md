<details>
<summary>SYSTEM DETAILS / EVIDENCE</summary>

ToolGraph is the sole featured system. Its [web dependencies](https://github.com/br3h/toolgraph/blob/main/apps/web/package.json), [engine dependencies](https://github.com/br3h/toolgraph/blob/main/apps/engine/package.json), [schema checker](https://github.com/br3h/toolgraph/blob/main/packages/schema-core/src/compat.ts), [code generators](https://github.com/br3h/toolgraph/tree/main/packages/codegen/src) and [database migrations](https://github.com/br3h/toolgraph/tree/main/supabase/migrations) support the architecture and stack. Python / FastAPI / MongoDB are also present in the [TeachBack waitlist backend](https://github.com/br3h/teachbackfinal/blob/main/backend/server.py); that repository is not presented as an equal flagship.

The system and security maps distinguish interests from published source. Moving signals and the hero’s ONLINE / BUILDING labels are interface artwork, not real operational activity, security posture or deployment monitoring. The site link is omitted because availability was not verified.

The telemetry chart counts unique br3h-attributed commits on owned public default branches in a rolling 90-day UTC-committer window. Language detection is scoped to recently updated selected repositories. Repository count includes all public repositories. CI/release observations remain dated in the [pulse snapshot](generated/pulse.json); they are not deployment-health assertions.

The activity figure counts twelve complete UTC weeks. Forks, archived repositories, this profile and the partial current week are excluded. Weekly bars are linear; the cumulative line sums those weeks on its own scale. Mobile cells represent weeks, not fabricated daily contributions. [Activity data + exact scope](generated/activity.json).

</details>

<details>
<summary>PROFILE AUTOMATION / BUILD NOTES</summary>

`data/projects.json` selects published systems; `data/status.json` defines observation windows. `scripts/generate-visuals.ts` builds original static artwork from that manifest and the actual workflow schedules. GitHub’s REST API powers `scripts/generate-pulse.ts` and `scripts/generate-activity.ts`. Renderers emit paired 1200-wide SVGs with compact layouts inside the same assets.

All motion is self-contained SVG CSS. Most elements assemble once; a few illustrative signals loop gently. Reduced motion shows final readable information through SVG media queries and native picture sources selecting the same artwork’s static fragment—no duplicate assets. GitHub interaction is native anchors, linked image panels and these disclosures—not JavaScript, hover-only controls or a simulated terminal.

API failures retain previous SVGs, snapshots and bounded README regions. The [daily pulse](.github/workflows/pulse.yml) and [weekly activity](.github/workflows/activity.yml) workflows remain local/inactive. When separately authorized for publication, their serialized refresh jobs use only the ephemeral `GITHUB_TOKEN`, with `contents: write` limited to the job that updates generated files.

Local verification: `npm run generate:visuals`, `npm run generate:pulse`, `npm run generate:activity`, `npm test`, `npm run verify`. Node.js 24.12 or newer. API generators accept `--now <ISO timestamp>` for reproducible inspection. No runtime dependencies, widget services, external fonts or PAT are required. [Brand mark](assets/brand/mark.svg).

</details>
